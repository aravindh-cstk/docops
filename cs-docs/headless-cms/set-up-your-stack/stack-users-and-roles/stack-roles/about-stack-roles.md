# About Stack Roles

## About Stack Roles

A **Role** is a collection of permissions that applies to all the users who are assigned to it. Using Roles, you can assign permissions to a group of users rather than assigning permissions individually.

**Note:** Any role you assign to a stack user will be reflected across all the branches of the stack. That user role will be able to access data of only the allowed branch(es) or branches associated with the allowed alias(es). Refer to our [Global Modules](/docs/headless-cms/global-modules) document for more information.

Roles enables you to set permissions on all/specific [entries](/docs/headless-cms/about-entries/), all/specific [assets](/docs/headless-cms/about-assets/), and all/specific [asset folders](/docs/headless-cms/create-a-folder/). While you can create a role, Contentstack has already defined roles, which you can assign to a user, named as “Admin,” “Developer,” and “Content Manager.”

**Additional Resource:** To know more about roles and their associated permissions, refer to the [Types of Roles](/docs/headless-cms/types-of-roles) article.

For example, if you create a role that has “Create” and “Delete” permissions on certain content types and assign this role to 20 users, all these 20 users will have "Create” and “Delete” permissions on all the entries of the assigned content types.
